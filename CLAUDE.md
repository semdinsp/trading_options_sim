# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project guidelines

See `AGENTS.md` in this directory for Phoenix v1.8 / LiveView / Ecto / HEEx conventions (usage-rules generated by `mix phx.new`). Those rules apply to all code written here and are not repeated below.

### PubSub: consumers subscribe on a remote app's PubSub, never broadcast on it

This app starts local `Phoenix.PubSub` servers under two *other* apps' names
(`TradingHub.PubSub`, `TradingSignal.PubSub`) so `:pg` can deliver those apps'
cross-node broadcasts here — correct, and explained at each child spec in
`application.ex`. The side effect is that this node *could* broadcast on either
bus, and every other node would receive it as though the owning app had sent it.
Nothing does today and nothing prevents it, which is why the rule is written
down: **subscribe on a remote app's bus, broadcast only on
`TradingOptionsSim.PubSub`.**

Topic strings for `TradingHub.PubSub` come from `TradingContract.Topics`
builders (`Topics.prices/1`, `Topics.prices_all/0`, …), not hand-written
literals — a renamed topic on the producing side then becomes a compile error
here instead of a relay that silently stops receiving ticks.

This app's own `TradingOptionsSim.PubSub` topics are not part of that contract
and stay as they are: `PriceRelay` broadcasts underlying ticks onto
`"prices:" <> symbol` locally, and `ContractMonitor`/`IBKRLive` subscribe to
them. Those strings are internal to this app on both sides, so a rename here is
already a same-repo change. `TradingSignal.PubSub` topics are resolved at
runtime via `SignalBus.request/1` rather than built from literals, so they are
outside the contract too.

Note that `"prices:*"` is not a real topic — `Phoenix.PubSub` has no wildcard
subscriptions. `IbPortfolio.HubClient` expands such a pattern through a private
lookup table before subscribing. Name the fan-out topic directly
(`Topics.prices_all()`) rather than relying on that expansion.
